## 2.1.0 (2026-10-17)

Apple revised the App Review Guidelines on 16 October 2026. This release follows that revision. It adds three patterns and no new guard rule, so it is a minor version.

### Changed

- Apple revised the App Review Guidelines on 16 October 2026, and the playbook follows the live text, checked on 17 October 2026 against [the revision note](https://developer.apple.com/news/?id=92th7e5i) and [Apple's safety post](https://developer.apple.com/news/?id=vvzx6cul).
  - 1.2 now names social media, user-generated content platforms, and AI content creation apps, lists nonconsensual intimate imagery, and warns of a Developer Code of Conduct violation for missing safeguards or violations left unfixed after notice. `APPLE-1.2-UGC-24H-ACTION` and `BOTH-AI-GENERATED-CONTENT` carry the new wording, and the UGC fix no longer promises a 24 hour window the guideline does not set.
  - Hidden, dormant, and undocumented features moved from 2.3.1 to the new 2.5.19. The 2.3.1 row in `docs/APPLE.md` and the `future_functionality` mapping now say so, and `RN-OTA-UNDECLARED` names the bait-and-switch risk.
  - 3.1.1(a) folds the Music Streaming Services Entitlement into the StoreKit External Purchase Link bullet and requires a permitted destination. `APPLE-3.1.1-EXTERNAL-LINK-REGION-GATING` and its row say so.

### Added

- Three patterns, each checked by hand because the evidence lives outside the project. `APPLE-2.3.14-CREATIVE-ASSET-CONTENT` (medium), `APPLE-2.5.19-HIDDEN-OR-DORMANT-FEATURE` (critical), and `APPLE-5-TRAFFICKING-CHILD-EXPLOITATION` (critical), with matching rows in `docs/APPLE.md` and two new lines in the pre-submission checklist.

## 2.0.0 (2026-10-16)

This release changes the licence and the release audit's exit codes, so it is a major version. Everything below landed since 1.0.0.

### Thanks

### Changed

- Shell tools are matched against an exact name list, which adds `runInTerminal` and `run_in_terminal`. An MCP tool whose name merely contains terminal or shell is no longer scanned.
- The default branch is now `main`. The CI trigger, the README badge and SECURITY.md follow it, and the bot branch ruleset excludes whichever branch is the default.
- The bot PR gate. The workflow from #442 closed every PR whose branch looked bot-generated, which caught the owner's own Jules scheduled tasks. It is replaced by a gate that closes only pull requests from bot accounts not on the allowlist (Jules, Copilot, Dependabot, GitHub Actions), without deleting the branch. Owner-run bot PRs stay open, land on the project board as Backlog through the auto-add workflow, and are reviewed by hand. The eleven Jules PRs closed on 14 September 2026 had their branches deleted by the old workflow and cannot be reopened.

### Fixed

- Workspace runners are scanned. `yarn workspace x <script>`, `pnpm --filter x`, `npm -w x` or `--prefix`, `bun --filter`, `turbo run`, `lerna run` and `nx run x:target` resolve the script or nx target in the package they name. Without a named package, `turbo`, `lerna` and `nx run-many` read every package, and a named package that cannot be found falls back to every package. The whole command is read as one runner, as in 1.0.0, with a plain `npm`, `pnpm` or `bun run` tried first so runner words inside its arguments never take over, and every runner in a compound command, a `$(...)` or backticks is read on its own too, so a later web build never masks an earlier submit script. The `bun ship`, `turbo ship`, `pnpm -r ship` and `nx ship mobile` shorthands and `nx run-many` or `nx affected` with `-t` or `--target` are read too. An nx command without `project:target` reads every package. An nx target whose options nest an object, such as `env`, is still read to its command. `bun run --filter x ship` and several `--filter` selectors in one command are read, as is lerna `--scope`, and a pnpm graph selector such as `web...` or `{apps/web}` is reduced to its package name. An exclusion-only filter such as `--filter '!docs'` reads every package. Recursive forms (`-r`, `--recursive`, `-ws`, `--workspaces`, `yarn workspaces foreach`) read every package, a scoped `@scope/name` matches only that package, and the root package.json always counts.
- Without jq or python3, a payload with more than one tool name field is scanned rather than trusted, so nested metadata cannot hide a Bash submit.
- A Tuist `Project.swift` purpose string counts as the key.
- The restore check now also covers a cross-platform purchase plugin app (1.0.0 checked only native StoreKit apps), where the plugin's purchase list call (getAvailablePurchases, queryPastPurchases) counts as the restore flow. A native StoreKit app still needs a real restore call, as in 1.0.0.
- The OpenCode plugin refuses a submit-looking command when the guard itself cannot run (missing file, crash, timeout), and logs the problem for other commands. It reads the command with quotes and backslashes removed and every whitespace run as one space, as the guard does. OpenCode loads both plugin folders, so a call one copy already checked is skipped by the other. Without node the plugin cannot be exercised, so the install ends with `Installed, but not fully verified.` instead of `Install verified.`
- Claude Code `doctor` fails when the registered hook is not a command handler or its timeout is under 30 seconds. Every non-Claude `doctor` says when this checkout is newer than the installed skill.
- A git commit whose message sits beside a `$(...)`, backtick, process or zsh `=(...)` substitution is scanned in full, so a submit run inside that substitution is never hidden as message text.
- An Android word inside a quoted argument, such as a lane parameter `notes:"test -p android"`, is text and never turns the Apple checks off. Each command in the line is read twice, once with quoted text kept and once with it blanked, and `#` comments dropped, on macOS bash 3.2 as on bash 5 (a test runs the guard under the system bash itself). A submit is recognised from the kept text, so a quoted lane name such as `fastlane "beta"` still counts, and its Android word only from the blanked text. Every submit must name Android itself, and any other command that is not known to be harmless keeps the Apple checks, so a harmless `echo -p android` beside an iOS lane never vouches for it. An Android build stays Android only when every other command beside it is known to be harmless (cd, echo, export, ls and similar) and holds no `$(...)`, backtick, process substitution or zsh `=(...)`. git is never on that list, because an alias, a configured diff helper, a filter or an fsmonitor hook can run anything, so a git command beside an Android build keeps the Apple checks on. Anything else, such as `npm run`, `make`, a script or `python3 upload.py`, may upload to Apple, so the Apple checks stay on. Any `ios`, `ipa` or Apple upload word anywhere in the command keeps them too, as before 2.0.0. On top of all this, the command must still pass the 1.0.0 Android rule (`build apk`, `assembleRelease`, `bundleRelease`, `run-android`, `--platform android` and the rest), so no command turns off the framework checks where 1.0.0 ran them. A real Android build in a repo that also holds an iOS app still skips the native Apple checks, by design. A flag form 1.0.0 did not know, such as `eas submit -p android`, still runs the Apple checks. A wrapped submit (`npm run`, `make`) is Android only when every command that is not known to be harmless names Android itself, so an `echo --platform android` beside `npm run ship` never turns the Apple checks off. A submit quoted inside a shell (`bash -c`, `sh -c`, `eval`, by path such as `/bin/bash`, or behind `env` or `sudo`) never takes an Android word from the outer arguments, because they never reach it. The same holds for a submit seen only inside quotes, such as one run by `python3 -c` or `ruby -e`.
- The trigger checks (is a camera, location or payment API used) read every source line raw, as in 1.0.0, so no comment rule can hide a live call, a Swift interpolation on a line led by `//` included, and a mention in a comment counts as it did in 1.0.0. Only the account deletion and ATT authorization implementation checks drop comments (the restore check reads source raw, as in 1.0.0), line by line with no string state, so a misread quote can never hide the lines after it. They drop block comment lines (the code after a closing `*/` on its line still counts), a trailing `//` and a closed `/* */` on the line, unless the rest of the line holds JSX or the marker sits inside a single, double or backtick quoted string (an escaped quote such as `\"` does not end the string, outside a Swift raw string, and a quote inside a JavaScript regex literal such as `/"/`, after an operator (`= ( , : & | ! ? { } ; + - * % < > ~ ^`) or `return`, is not a string quote). A removed inline comment leaves a separator, so the words on either side never join into a marker such as `account deletion`, so a deletion written only in a comment never counts and real code between two quoted markers always does. An HTML `<!--` opens a comment only at the start of a line or right after a tag, and one that never closes was a misread string, so the markup after it still counts.
- `InfoPlist.strings` is no longer read at all, so translated text can never stand in for StoreKit, a Restore Purchases control or any other implementation.
- With neither jq nor python3, a payload from a named tool that is not a shell (such as Read) stays quiet, the same as with a parser.
- A commit or gh message whose quote is left open at a line end spans lines in bash, so the whole command is scanned unmasked and a submit after it is never hidden.
- Kiro's PowerShell tool (`execute_pwsh`) is read like `execute_bash`.
- A purpose string in an XcodeGen include file, an Nx `project.json`, a Tuist helper under `Tuist/` or a Cordova `config.xml` counts, as in 1.0.0.
- A jq-only uninstall on Windows removes an owned hook under any matcher, so an old `Bash`-only entry no longer survives.
- Copilot `doctor` checks the Windows `powershell` handler against the exact command the installer writes, so an edited handler fails.
- When the guard cannot write its scan buffer beside its file list, it falls back to `/tmp` as before 2.0.0, so the source scan still runs.
- A git message is treated as text only for a plain `git commit`, `tag` or `notes` (with at most `-C <dir>`). A git alias or any other global option keeps the whole command scanned, because an alias can run its arguments.
- metadata-audit needs a Terms of Use or EULA link in the description, with a path naming terms, EULA, conditions or licence, or the whole word ToS, AGB or legal, and never a privacy page. Apple's standard EULA counts only as that page on apple.com, never as text inside another URL, and the word terms or EULA in the description or promotional text. A separate `terms_url` field, a privacy link, or a host that merely contains tos (photos.app) no longer satisfies it. With `--check-urls`, a malformed URL is reported instead of skipped.
- Two installs of one tool in different config folders (two `CODEX_HOME` or `QWEN_HOME` values) each own the shared skill. Uninstalling one keeps the skill for the other.
- Kimi uninstall restores the config byte for byte, trailing newlines and CRLF line endings included. A CRLF config is matched and stays CRLF on every platform, so a second install changes nothing.
- `--tool all` expands a `QWEN_HOME` written as `~\folder` the same way the installer does.
- The agent paste block in the README and the guard table in the skill list all twelve supported tools.
- The guard catches Grok Build's native shell tools (`run_terminal_command`, `run_terminal_cmd`, `monitor`, `bash`). Before, a real Grok session ran a submit command without any check. The Grok install matches all four, doctor tests the real payload, and install repairs an old `Bash`-only entry.
- A command segment that runs an Apple upload is never treated as Android only. An Android word must be the actual gradle task, flutter build verb or platform flag, never text inside another tool's argument.
- metadata-audit keeps the longest value when two files supply the same field, and reports the conflict instead of hiding an overlong name. Every combination of the conflicting values is audited too, across fields, up to 4096 combinations (the report says when it stopped early), so no pairing of a kept and an unkept value hides a rejection risk. A value in a nearer folder, a locale or on the command line overrides a conflict between files further up, and the last command line value for a field wins whatever alias named it.
