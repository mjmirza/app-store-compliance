# Changelog

All notable changes to this playbook are recorded here. The format follows Keep a Changelog, adapted to plain punctuation.

## Unreleased

### Changed

- The bot PR gate. The workflow from #442 closed every PR whose branch looked bot-generated, which caught the owner's own Jules scheduled tasks. It is replaced by a gate that closes only pull requests from bot accounts not on the allowlist (Jules, Copilot, Dependabot, GitHub Actions), without deleting the branch. Owner-run bot PRs stay open, land on the project board as Backlog through the auto-add workflow, and are reviewed by hand. The eleven Jules PRs closed on 14 September 2026 had their branches deleted by the old workflow and cannot be reopened.

A rule asked whether the tree held the risky symbol and whether it held the mitigating one, and a clean sibling app answered for a broken one. The guard now discovers app roots (an Expo, React Native, Flutter, or Capacitor app, an Android project, an Xcode project) and when two or more exist below the project root, or the root is itself a framework app with nested framework apps, each is scanned on its own with its own `App.` section, platform line, and findings under the single `Project.` header. The two probes that read the whole tree directly (privacy manifest presence and R8 minification) honour the same app boundary, the find prune escapes glob characters in an app name, a project path that is itself a symlink is walked through its target instead of scanning empty, and the temp file pair is created once and removed on exit. 57 new test cases, 184 total, pinning every counterexample from three adversarial review rounds and three independent reviewer passes, including a no-Gradle R8 regression that the byte comparison against the previous guard caught and the tests had not.
- The guard's hook-mode payload parser was not JSON-aware (#610, reported and measured by mj-deving). The regex extraction stopped at the first escaped quote, so `cd "$CLAUDE_PROJECT_DIR/apps/app" && npx eas submit --platform ios` reduced to two characters and the guard exited 0 unscanned, and a backslash-newline continuation left the JSON newline escape literal, so `eas submit` split across two lines never matched. The command is now read from `.tool_input.command` (or a top-level `command`) with jq, then python3, then a backslash-aware fallback when neither is installed. Backslash-newline continuations fold into one space, and bare newlines stay as separators, so a trigger split across two separate commands is never invented. In hook mode a block now writes the report to stderr, the only stream Claude Code shows on exit 2, so the reason no longer arrives empty. A pass stays on stdout and standalone mode is unchanged. An adversarial review of the fix added four more guards. the trigger is matched against the raw command with quote characters stripped, so `eas "submit"`, `bash -c 'eas submit'`, and a submit inside a `python3 -c` string are all scanned, and only a single simple line led by an inert text command (`echo`, `printf`, `grep`, `cat`, `head`, `tail`, `wc`, `sort`, `uniq`, `tee`) with no substitution, pipe, or separator has its quoted spans and trailing comment blanked, so a plain echo or grep that mentions a submit never blocks while `echo "$(eas submit)"` and a `git` alias still scan. jq and python3 are each probed with a trivial run and their real exit status is checked, so a present but broken interpreter (the macOS python3 stub without Command Line Tools, a stale pyenv shim, a jq that dies on real input) falls through instead of silencing the guard, while a payload python3 genuinely rejects as invalid JSON stays silent. A leading `cd <dir> &&`, when it is the only directory change in the command and resolves inside the project, scopes the scan to that app, which is how an EAS monorepo submits. A payload whose `tool_name` is not Bash, or that carries more than one JSON document, is never scanned. A hook timeout signal flushes the buffered report to stderr, and when no temp file can be created the report stays on stdout as before with only the block reason line added on stderr. 80 new test cases, including runs with jq and python3 removed from PATH, a present but broken interpreter on PATH, and every counterexample from four adversarial review rounds.
